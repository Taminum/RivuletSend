# @p2p/android — RivuletSend Android app

React Native (bare) app. Reuses `@p2p/shared` (the protocol) directly, same as
`web` and `desktop`. The web UI is **not** reused — RN screens are native.

## Status: Step 1 — WebRTC probe

This first slice deliberately builds only the riskiest unknown from the plan: a
`react-native-webrtc` data channel through the real signaling server, plus a
**backpressure probe** that verifies whether the browser-tuned flow control
(`bufferedAmount` / `bufferedamountlow`, tuned in `packages/web/src/fileTransfer.ts`)
behaves the same here. Everything else (storage/SAF, crypto, QR, background
service, real UI) comes after this is confirmed on a real device.

- `src/rtc/webrtc.ts` — the single import site for the native WebRTC classes.
- `src/peer/backpressureProbe.ts` — signaling + data channel + watermark-gated
  send loop, reporting throughput and whether `bufferedamountlow` fires.
- `App.tsx` — two-phone harness: one **Creates** a room, the other **Joins**;
  the creator sends a 64 MB dummy stream and shows the stats.

## The native `android/` folder is generated, not committed

A correct bare-RN `android/` tree (Gradle, Kotlin `MainApplication`, the binary
gradle wrapper) is generated by the RN CLI — hand-writing it is error-prone and
untestable. CI (`.github/workflows/android.yml`) generates it from the pinned RN
template, links `react-native-webrtc`, and builds the APK. Locally you can do the
same once:

```bash
# from the repo root, one-time, to work on the app locally:
npx @react-native-community/cli@15 init RivuletSend --version 0.75.4 --directory /tmp/rs-native --skip-install
cp -r /tmp/rs-native/android packages/android/android
# then: pnpm install, and `pnpm --filter @p2p/android android` with a device attached
```

## Testing (real device — required)

The plan calls for real-device testing; an emulator won't tell you the truth
about WebRTC throughput or backpressure.

1. Install the APK from the CI artifact on **two** Android phones.
2. On phone A: set the signaling URL (default `wss://send.tarmalion.ru/ws`) → **Create room**.
3. On phone B: enter the code → **Join**. Wait for "data channel open".
4. On phone A: **Send 64 MB probe**. Read the result card:
   - **Throughput** — sanity-check it's reasonable over your network.
   - **bufferedamountlow: fires ✓ / UNRELIABLE ✗** — the key finding. If it's
     unreliable, `peer.ts`'s backpressure port needs a polling fallback (the
     probe already demonstrates one) before large transfers are built on it.
   - **Max buffered** — should hover near the 4 MB high-water mark, not balloon.
